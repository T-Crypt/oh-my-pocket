# Open issue triage, 2026-10-16

A dated triage of the open issues on the upstream project, `TannerMidd/pi-pocket`, read with `gh issue list --state open`. This fork, `T-Crypt/oh-my-pocket`, has issues disabled, so every issue below is upstream's. This note is not part of Pi Pocket's documentation; it records where each issue stands for this fork.

## Already covered here

- #75 Plan mode: let tools marked read-only run. The `oh-my-pocket` branch implements the intent through `host.readOnlyCalls`, a map from a tool name to a check of its arguments. Plan mode also lets `git -C <dir>`, `git branch -a`, and commands that write to `/dev/null` through. Upstream's issue names `readOnlyHint` instead. Nothing to do here.

## Bugs

- #83 The Plan chip keeps the focus after a click, so Enter turns plan mode back off. A small keyboard defect, still open.
- #57 Changes totals omit additions in untracked text files. This touches the Changes tab the fork keeps, so it would need a port.
- #72 PiP's getting-started hiccup loses the suggestions. The owner says 0.14 adds a model button in the PiP header.
- #71 Scheduled messages leave the session where it was.

## Feature requests

- #89, #88, #87 Sandboxed artifacts: persistent interaction state, a follow-up back to Pi, and an `artifact_inline` tool for versioned HTML.
- #79 Show Pi's current thought while it works.
- #77 Let the folder square in the session list show the session's state.
- #82 A density appearance option.
- #70 Show only the current session's messages.
- #47 Image support in PiP chat.
- #61 HTTP routes, sidebar items, and panels for drop-in extensions. The owner calls this the highest priority for the next major release.
- #35 Native slash commands for extensions, still a draft, with an implementation in PR #36.
- #24 File upload and download in the Files tab.

## Setup and configuration

- #39 Read a session folder's `.pi/settings.json`, as Pi does.
- #29 No local models detected. The owner's answer is to add the provider to `~/.pi/agent/models.json`; the `pi-local` extension is a Pi extension, and Pi Pocket runs on Pi Durable.
- #67 MCP support. The owner says Pi Durable has no MCP yet, so a Pi `mcp.json` does not reach Pi Pocket. A Durable drop-in could add stdio MCP.

## What to do with them

- Nothing here blocks this fork, and the batteries do not depend on any of it.
- #83 and #57 are small and self-contained, so they are the two most likely to be worth porting.
- #61 and #67 depend on Pi Durable and on upstream's direction. Leave them to upstream.
